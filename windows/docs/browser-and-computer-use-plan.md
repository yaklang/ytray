# Browser Use 与 Computer Use 实施清单

先做第 3 项的 Windows 本地操作，用 Memfit 打开一个文件夹验收。浏览器部分先用现有引擎链路验证第 1 项的页面反馈，再用第 2 项接入独立的本地通道。

## 1. 浏览器操作反馈

- 在目标标签页的内容区显示细红边。定位到点击或输入的目标时，由扩展在现有 Shadow DOM 浮层里画元素框，鼠标事件穿过提示层。
- 操作说明由执行结果更新。切换标签页、导航到新文档或结束任务时清理旧目标框，扩展图标或 YTray 保留连接状态。
- 如果提示需要跨越标签栏、地址栏或系统弹窗，使用 YTray 的原生覆盖层。窗口外框跟随目标窗口的可见范围、位置和缩放。

验收时滚动、缩放并在两个标签页间切换。元素框应跟随实际目标，另一标签页可以正常操作。现有 Windows 桌面提示见 [原生反馈](../src/Native/WindowsOperationFeedback.cs)。

插件已实现网页元素红框。Chromium 实测覆盖输入、点击、滚动、125% 浏览器缩放、鼠标穿透、切换标签页和刷新清理。

## 2. 独立 Browser Use

链路为 **支持 MCP 的 Agent → YTray 选择或启动浏览器实例 → 扩展观察和操作目标标签页**。YTray 负责浏览器运行时、实例、独立 Profile 和代理配置。扩展负责页面观察、操作和红框。Yak 引擎也可以作为调用方。

- 正式安装版由 YTray 注册自己的 Native Messaging Host，绑定到扩展 ID。YTray 接收扩展的连接，既有 Yak 配对入口继续服务引擎调用。
- 初期提供共享标签页的页面摘要、点击、输入和滚动。每次操作匹配浏览器实例、标签页和当前文档。页面刷新或授权撤销后，旧目标引用失效。

验收时关闭 Yak 引擎，用另一个 MCP 客户端在已共享标签页完成一次普通页面操作。两个浏览器实例同时打开时，操作和红框应落在用户选定的页面。

首版 Windows `ytray-browser` 通过插件手动接入当前网页，提供列页、观察、点击、输入和滚动五个工具。[浏览器控制用法](../README.md#浏览器控制与-mcp)

Windows 双实例验收时关闭了 Yak 引擎。OpenCode 使用本地 Qwen3-4B，通过六次 MCP 调用完成了发现授权页、观察、输入、提交、滚动和读回。授权页显示 `Saved: YTray Browser Use`，滚动了 700 像素，输入和提交时都显示了红框。另一实例的输入框、提交结果和滚动位置保持初始状态，未观察到红框。跨实例引用被拒绝，撤销共享和刷新后旧页面 ID 失效。

验收使用两个独立的临时 Chrome for Testing Profile。测试夹具在临时插件副本中预授了浏览器的 Native Messaging 权限，每次网页共享仍通过插件的「共享此页」执行。Windows x64 测试包内置的 0.2.9 插件保留首次使用的权限提示。

### 托管实例自动接入

Codex 在任务中选择浏览器或已有标签页，网站访问由单独的站点权限管理。标签页保持身份，导航后的页面状态由 Agent 重新观察。YTray 用已有的受管实例启动页交付实例身份，扩展将当前普通网页自动注册到独立 MCP。Agent 根据实例角标、标题或网址定位目标。[OpenAI 官方浏览器扩展说明](https://learn.chatgpt.com/docs/chrome-extension#start-a-browser-task-from-chatgpt)

- 浏览器控制开启一次，YTray 下次启动恢复服务和配置。内置企业版插件在安装时声明 Native Messaging。外部浏览器可以继续在插件里共享单页。
- 同一标签页同源跳转后保持原页面 ID，旧节点和快照作废。跨源跳转、页面动作打开的新标签页及手动暂停的标签页等待用户接入。
- Windows 双实例测试使用内置插件的权限声明。关闭 Yak 后，OpenCode 通过七次独立 MCP 调用完成 A 实例的表单搜索、结果页读回和滚动。B 实例保持初始输入、滚动和红框状态。另行核对了刷新、跨实例引用、新标签页、跨源和停止共享。测试页通过本机 HTTP 提供。

### 从浏览器实例进入任务

用户可以指定浏览器运行时（如 Edge 或 Chrome for Testing）、既有实例（如 A 或 B），也可以明确要求新开实例。YTray 管理实例的独立 Profile、代理和历史恢复。参考 Codex 的现有标签页绑定方式，进入任务后用实例 ID 和标签页 ID 固定目标。页面跳转后重新观察，元素引用以新页面为准。

- 已有实例里有唯一匹配的标签页时直接复用。同一家浏览器可同时运行多个独立实例。同一网站在 A、B 都打开时，用用户指定的实例或任务已绑定的实例定位，仍有歧义时才询问。
- 用户要求在运行中的指定实例打开网址时，在该实例新建标签页。用户要求新开实例时，按指定运行时启动一个独立 Profile，再等待扩展接入该次启动的目标页。恢复历史实例继续使用该实例原有的 Profile。
- 独立 `ytray-browser` 提供 `browser_list_runtimes`、`browser_list_instances` 和 `browser_open`。插件通过每个 Profile 的连接接收开页请求，YTray 用请求 ID、实例 ID 和目标来源核对插件返回的具体标签页。运行中的实例即使只有空白页也能开页。新实例用一次 `browser_open` 等待插件接入并返回 `page_id`。
- `browser_focus` 可以显示具体标签页。当前可见页面的元素框继续由扩展绘制，观察回包提供红框颜色和边界，便于核对页面身份。
- Windows 实测关闭 Yak，Chrome A 和 B 同时运行且使用独立 Profile。A 的百度搜索 `yaklang` 后保留原页面 ID，B 新开 B 站且保留原标签页。Chrome for Testing 新实例自动接入百度，并用返回的 `page_id` 完成搜索。通过 MCP 读回 A/C 的搜索框、B 的首页链接红框，其他实例没有对应红框。
- 两个实例并行打开同一个网址、同一实例重复打开同一网址，均返回各自的新页面 ID。跨源重定向返回 `origin_changed`，跨实例使用快照返回 `stale_node`。Windows 切窗后若 Chromium 仍报告页面不可见，`browser_focus` 会返回 `page_not_visible`，页面可见后可继续核对红框。

## 3. Windows Computer Use

第一项是 `open_folder(path)`。通过现有 `ytray-system` MCP 发现并调用，沿用电脑控制的授权和交互桌面检查。参数为 Windows 可访问的绝对目录。YTray 校验后交给 Windows Shell，返回规范化路径和系统受理状态。需要在 Explorer 中继续操作时，可以用现有的窗口观察和输入工具。

- Memfit 验收可以直接说「打开 `C:\Code\golang\ytray` 文件夹」。工具调用应为一次 `open_folder`，并看到 Explorer 打开对应目录。
- 检查目录不存在、路径指向文件、路径不完整、电脑控制关闭，以及只读或应用范围受限时的结果。
- 通用桌面动作的提示和光标动画异步绘制。动作完成并取得最新状态后即可回包。[Windows MCP 使用说明](../README.md#电脑控制与-mcp) · [通用动作编排](../src/Core/SystemControl/ComputerUseTools.cs)

同机对照使用同一个 Windows 测试程序，每版运行三轮，工具参数为 `include_screenshot:false`。YTray 回包耗时中位数从点击 3.03 秒降至 1.12 秒，输入从 4.76 秒降至 3.00 秒，滚动从 4.70 秒降至 2.82 秒。Memfit 验收时记录整轮耗时和工具调用次数。

### 当前修复

Windows 事件日志定位到托管 `TextPatternRange.GetText` 在 WPF 输入框读取选区时触发原生访问冲突。输入已经投递，读取状态却让控制进程退出。焦点属性和选区现在通过原生 UI Automation COM 读取。验收覆盖中文及 emoji 输入、插入点和实际选中文字，以及两次调用前后的控制进程 PID。[焦点读取实现](../src/Native/WindowsFocusContext.cs) · [Windows UIA 选区接口](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationtextpattern-getselection)

同一台 Windows 机器、同一个 WPF 测试窗口，开启截图，每版运行三轮。与上一版对比，按编号输入的 MCP 回包耗时中位数从 3.37 秒降至 1.79 秒，随后 `Ctrl+A` 从 3.04 秒降至 0.96 秒。新版每轮均读回实际选区，控制进程 PID 在输入及全选前后一致。

### 输入反馈、观察和验收

- 键盘提示直接定位焦点。点击和滚动的动画最长 150 毫秒，完成时光标直接定位目标。支持 UIA 的按钮和滚动区域直接调用控件动作。坐标输入需要注入鼠标时，在同一个输入批次恢复原位置。卡片按目标显示器的工作区定位，测试覆盖实际双屏切换和负坐标、高缩放比例的工作区计算。
- 近期控件编号在原生进程内验证身份、名称和位置。聚焦、替换、输入、提交合在一次调用中，每个输入阶段检查焦点。控件变化时返回最新界面和动作是否开始。默认滚动用窗口几何定位，短时间内的坐标输入复用已有截图。控件名称或值变化可唤起状态读回，超时也会读回当前界面。关闭截图时保留控件编号和焦点。
- `open_folder` 直接走 Windows Shell，已核对 Explorer 的实际目录。单文件定位还需核对 Explorer 的选中结果。

同机 WPF 测试程序关闭截图，每版三轮。点击的本机 MCP 回包耗时中位数为 1.75 → 0.81 秒，输入为 2.27 → 0.83 秒，替换并提交为 3.38 → 0.77 秒。新版组合输入每轮只有一次最终界面读取。无图滚动与定位共两次调用，核对了应用的实际滚动位置。

### 请求取消与界面状态

- 控件编号和截图坐标随 `state_id` 一起传入。用两个 MCP 客户端交替读取同一个窗口，核对旧编号、旧缩放尺寸的坐标和窗口移动前的坐标均被拒绝。使用新状态后核对按钮确实执行一次。
- 两个 MCP 客户端可使用相同的 JSON-RPC ID。用 `notifications/cancelled` 取消其中一个排队动作，核对另一个客户端继续执行。在组合输入全选阶段发出取消，核对测试窗口保留原文和选区，提交计数为零，原生控制进程保持连接。

### 微信实机回归

- 用正式的 `ytray-system` MCP 端点先列出微信窗口，再验证 `launch_app` 复用登录后的主窗口。检查 `window_id` 和 PID，普通观察的图片数为零。
- 微信当前的 UI Automation 控件视图和原始视图只提供窗口容器。观察先返回 `window_only`，需要定位搜索框时再请求截图。
- 旧版前台 Unicode 键盘投递在微信的全角逗号附近产生错字。Unicode 窗口消息路径通过 MCP 的 `type_text` 投递同一段文字，在搜索框核对读回。非空文字的替换或提交采用分步调用，保证客户端可以在提交前核对内容。

### Memfit 复测

用同一个模型和同一组提示分别跑打开目录、填表提交、滚动后定位。打开目录以 Explorer 的目标路径为准，填表以实际输入和提交状态为准，滚动以可见内容变化为准。记录任务耗时与 MCP 调用数。YTray 日志中的 `control.timing` 提供队列、预检、投递、界面读回、截图耗时和调用计数。标准 Win32、Electron、不同 DPI 实机、中文输入法和 RDP 可继续用这组任务扩展覆盖。
